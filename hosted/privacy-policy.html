プライバシーポリシー Privacy Policy

最終更新: 2026-10-20
対象: Chrome 拡張機能「SR Data Extraction」（sr-data-extraction-plugin） Last updated: 2026-10-20
Applies to the Chrome extension “SR Data Extraction” (sr-data-extraction-plugin)

本拡張は MIT ライセンスの OSS です。開発は JSPS 科研費 25K13585 の助成を受けています。このページは、Chrome ウェブストアの審査および利用者への開示のために、本拡張が扱うデータとその流通経路を説明します。 This extension is MIT-licensed open-source software, developed with support from JSPS KAKENHI Grant Number 25K13585. This page explains, for Chrome Web Store review and for our users, what data the extension handles and where it flows.

要点 Summary

本拡張の開発者が運用するサーバーは存在しません。 利用者のデータが開発者側に送信・保存・収集されることは一切ありません。データはすべて、利用者自身が契約・所有する以下の 3 者の間でのみ流通します。 There is no developer-operated server. No user data is ever transmitted to, stored by or collected by the developer. All data flows only between the following three parties, all of which the user owns or contracts with directly.

  1. 利用者のブラウザ（本拡張の実行環境） The user’s browser, where the extension runs
  2. 利用者の Google アカウント（Google Sheets = プロジェクト DB、Google Drive = PDF・抽出テキスト・ログの実体） The user’s Google account (Google Sheets as the project database; Google Drive for PDFs, extracted text and logs)
  3. 利用者が自分の API キー（BYOK: Bring Your Own Key）で契約または指定する LLM API（Gemini API、OpenRouter、Anthropic、Azure OpenAI、利用者指定の OpenAI 互換 API） The LLM API the user contracts with or specifies using their own key (BYOK): Gemini API, OpenRouter, Anthropic, Azure OpenAI, or any user-specified OpenAI-compatible API

例外として、Google Drive のファイルを選ぶときだけ、開発者が GitHub Pages に置いた静的ページと Google Picker を使います（→ ファイル選択（Google Picker））。このページもデータを保存・送信しません。 The one exception: when you pick files from Google Drive, the extension uses a static page the developer hosts on GitHub Pages together with Google Picker (see File selection (Google Picker)). That page does not store or send your data either.

開発者は、利用者が取り込む論文・プロトコル・抽出結果について権利を主張せず、それらを受け取らず、AI の学習にも使いません。 The developer claims no rights in the papers, protocols or extraction results you bring into the extension, never receives them, and never uses them to train AI models.

Google ユーザーデータへのアクセス範囲 Scope of access to Google user data

本拡張が要求する OAuth スコープは以下の 2 つ のみ です。 The extension requests only these two OAuth scopes.

  • https://www.googleapis.com/auth/userinfo.email — サインインしたアカウントのメールアドレスの取得。「誰が抽出・判定したか」の記録（監査証跡）と、次回サインイン時のアカウント指定にのみ使用します userinfo.email — the signed-in account’s email address, used only to record who extracted or decided a value (audit trail) and to preselect the account at the next sign-in
  • https://www.googleapis.com/auth/drive.file — 利用者が Picker で明示的に選択したファイルと、本拡張が作成したファイルだけ にアクセスします（プロジェクト DB の Google Sheets の読み書きもこの範囲で行います）。Drive 全体を読むスコープ（drive.readonly 等）や、全スプレッドシートへアクセスする spreadsheets スコープは要求しません drive.file — access limited to files the user explicitly picks and files the extension creates (the project spreadsheet is read and written within this scope). Broader scopes such as drive.readonly or spreadsheets are never requested

本拡張は、Google API から取得したユーザーデータを、上記の機能提供以外の目的（広告・分析・第三者への提供・機械学習モデルの学習等）に 一切使用しません。Google API Services User Data Policy（Limited Use 要件を含む）を遵守します。 User data obtained through Google APIs is never used for anything beyond the features described above — no advertising, analytics, transfer to third parties, or model training. The extension complies with the Google API Services User Data Policy, including its Limited Use requirements.

LLM API への送信について Transmission to the LLM API

AI 抽出を実行すると、対象論文の本文テキストと抽出指示プロンプトが、利用者が設定した LLM API（Gemini API、OpenRouter、Anthropic、Azure OpenAI、または利用者指定の OpenAI 互換 API）へ送信されます。送信先によるデータの取り扱いは、その運営者の利用規約・プライバシーポリシーに従います。本拡張はプロバイダを仲介せず、利用者のブラウザから直接 API を呼び出します。 Running an extraction sends the paper’s text and the extraction prompt to the LLM API the user configured (Gemini API, OpenRouter, Anthropic, Azure OpenAI, or a user-specified OpenAI-compatible API). How that provider handles the data is governed by the provider’s own terms and privacy policy. The extension does not proxy the request: the call is made directly from the user’s browser.

OpenAI 互換 API を指定する場合、本拡張は保存前に接続先の scheme + hostname pattern を表示し、Chrome の実行時ホスト権限を利用者へ要求します。HTTP は localhost、127.0.0.1、[::1] に限って許可します。loopback HTTP の通信は暗号化されません。 For OpenAI-compatible endpoints, the extension shows the scheme and hostname pattern before saving and requests the corresponding Chrome runtime host permission. Plain HTTP is allowed only for localhost, 127.0.0.1 and [::1]; loopback HTTP traffic is not encrypted.

学術研究目的のデータ抽出（テキスト・データマイニング）は、日本の著作権法上の権利制限規定（第 30 条の 4 等）の範囲内であるとの整理に基づいています。 Text and data mining for academic research is treated as falling within the limitations and exceptions of Japanese copyright law (Article 30-4 and related provisions).

なお、AI 機能を使うと、PDF の本文やページ画像が利用者の選んだ LLM へ送られます。出版社の利用条件と送信先の規約を確かめてください。 Note that using the AI features sends the PDF text or page images to the LLM you chose. Check the publisher’s terms of use and the terms of that provider.

プロバイダごとのデータの扱い How each provider handles your data

送った内容をプロバイダがどう扱うか（保存期間・人によるレビュー・モデルの学習への利用）は、プロバイダと契約の種類によって違います。使う前に各社の規約を確認してください。 How a provider handles what you send (retention, human review, use for model training) depends on the provider and on your plan. Check each provider’s terms before use.

  • Gemini API: 無料枠（課金を有効にしていない Google Cloud プロジェクト）では、送った内容と応答が Google の製品の改善に使われ、人が読むことがあります。Google は無料枠へ機密情報や個人情報を送らないよう求めています。未公開のデータや機密資料を扱うときは、課金を有効にした有料枠で使ってください。根拠: Gemini API 追加利用規約 Gemini API: on the free tier (a Google Cloud project without billing enabled), what you send and the responses are used to improve Google’s products, and humans may read them. Google asks users not to send confidential or personal information to the free tier. Use a billing-enabled paid tier for unpublished data or confidential material. Source: Gemini API Additional Terms of Service
  • OpenRouter: リクエストを上流のプロバイダへ転送します。データの扱いはモデルと上流のプロバイダごとに違います。OpenRouter の設定とプライバシーポリシーを確認してください OpenRouter: forwards requests to upstream providers, and data handling differs by model and upstream provider. Check your OpenRouter settings and its privacy policy
  • Anthropic・Azure OpenAI・利用者指定の接続先（ローカル LLM を含む）: 各社（接続先の運営者）の規約に従います Anthropic, Azure OpenAI, and user-specified endpoints (including local LLMs): governed by the terms of each provider (or whoever operates the endpoint)

ファイル選択（Google Picker） File selection (Google Picker)

Manifest V3 では Google Picker のスクリプトを拡張の中で読み込めないため、Drive のファイルやスプレッドシートを選ぶときだけ、次の流れを使います。 Manifest V3 does not allow loading the Google Picker script inside the extension, so file and spreadsheet selection works as follows.

  1. 拡張が、開発者が GitHub Pages に置いた静的ページ https://youkiti.github.io/sr-data-extraction-plugin/picker.html を新しいタブで開きます。このページが Google Picker（apis.google.com）を読み込みます The extension opens a static page the developer hosts on GitHub Pages, https://youkiti.github.io/sr-data-extraction-plugin/picker.html, in a new tab. That page loads Google Picker (apis.google.com)
  2. ページから要求を受けると、拡張は送信元のタブ・ページの URL・起動ごとの使い捨ての値（nonce）を確かめたうえで、drive.file スコープの OAuth アクセストークンを拡張のメッセージ応答で渡します。トークンは URL に載せません When the page asks, the extension checks the sending tab, the page URL and a one-time value (nonce) created for each launch, then hands over an OAuth access token for the drive.file scope in its message response. The token is never put in a URL
  3. ページはトークンを Picker の呼び出しにだけ使い、保存も外部への送信もしません。選ばれたファイルの ID と名前を拡張へ返し、タブは閉じられます The page uses the token only to call Picker; it neither stores nor sends it anywhere. It returns the IDs and names of the chosen files to the extension, and the tab closes

ページのソースは hosted/picker.html で公開しています。GitHub Pages の配信は GitHub の、Picker は Google の規約に従います。 The page source is public at hosted/picker.html. Delivery via GitHub Pages is governed by GitHub’s terms, and Picker by Google’s.

データの保存・削除 Retention and deletion

  • すべてのデータは利用者自身の Google アカウントとブラウザ内のストレージに保存されます。削除は、利用者が Google Drive / Sheets 上のファイルを削除し、拡張を削除（またはブラウザのストレージをクリア）することで完結します。 All data lives in the user’s own Google account and in the browser’s extension storage. Deleting the files in Google Drive / Sheets and removing the extension (or clearing browser storage) removes everything.
  • OAuth アクセストークンは chrome.storage.session に置き、ブラウザを閉じると消えます。サインアウトするとトークンを失効させます。 The OAuth access token is kept in chrome.storage.session and is cleared when the browser closes. Signing out revokes the token.
  • LLM API キーは暗号化せずに chrome.storage.local に保存します。同じ Chrome プロファイルを使える人は読める可能性があります。共用の PC では、自分専用の Chrome プロファイルで使うか、使い終わったら拡張を削除してください（拡張を削除するとキーも消えます）。 LLM API keys are stored unencrypted in chrome.storage.local, so anyone with access to the same Chrome profile may be able to read them. On a shared computer, use your own Chrome profile, or remove the extension when you are done (removing it also deletes the keys).
  • 本拡張をアンインストールすると、chrome.storage 内の設定（API キー・メールアドレス・既定モデル等）は Chrome によって削除されます。Google Drive / Sheets 上のファイルは利用者の資産としてそのまま残ります。 Uninstalling the extension makes Chrome delete its chrome.storage settings (API keys, email address, default model). Files in Google Drive / Sheets remain, as they belong to the user.

第三者提供・データ販売 Third parties and data sales

本拡張は、利用者のデータを第三者へ販売・提供しません。開発者はデータを収集しないため、そもそも提供しうるデータを保持しません。 The extension neither sells nor discloses user data to third parties. The developer collects no data and therefore holds nothing that could be disclosed.
