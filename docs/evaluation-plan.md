## 4. 評価 A: Cochrane の解析データ（#356、主結果）

### 4.1 データの出所

Cochrane-bench は、PMC のオープンアクセスで本文を読める Cochrane レビューの RevMan データパッケージから、レビュー著者がメタ解析に入れた研究ごとの数値を gold にしている。組み入れ研究の本文は、PMC のオープンアクセスにある報告だけを使う（2026-10-10 の決定）。レビューのライセンスで層を分ける: `cc-by`（レビューが CC BY）と `cc-by-nc`（CC BY-NC 系）。

### 4.2 評価セット

2026-11-22 の本人の決定: **両方の層の、群ごとの数値（二値と連続）**。

| 層 | レビュー | 研究 | 項目（解析 × 研究） | 値 |
|---|---:|---:|---:|---:|
| cc-by | 2 | 42 | 223（二値 144・連続 79） | 1,050 |
| cc-by-nc | 15 | 102 | 924（二値 585・連続 339） | 4,374 |
| 合計 | 17 | 144 | 1,147 | 5,424 |

数え方: Cochrane-bench `abd2102` の `data/processed/<tier>/numeric_tasks/` の課題ファイルのうち、`data_type` が `dichotomous` か `continuous` の項目を 1 つ以上持つ研究（2026-11-22 に数えた）。値は、二値が群ごとの events と N（4 値）、連続が群ごとの mean・SD・N（6 値）。

- **含めない**: DTA の 2×2 表と GIV（どちらも cc-by-nc にだけある）。群ごとの数値ではなく、#356 の「最初に測るのは群ごとの数値」（2026-10-10）の範囲外。cc-by-nc の 300 研究のうち、二値・連続の項目を持たない研究はこれで外れる
- **入力の文書**: 拡張は PDF を読むので、各報告の PDF を使う（XML は使わない）。研究のオープンアクセスの報告に PDF が 1 本も無い研究は外し、件数を REPORT に書く。PDF の文字の層は、ハーネスで本番と同じ pdf.js の処理で取り出す
- 課題ファイルの研究数・項目数・値の数は、実行の前に数え直し、上の表と違えば理由を REPORT に書く

### 4.3 cc-by-nc の参照の裁定

cc-by-nc の参照のラベル（§5.1）は、本人の裁定が残っている（2026-11-09 の時点で 233 単位、ラベルの無い値が 305）。

- 実 API の実行は裁定の前に流してよい。**採点は、評価セットに入る値のすべてにラベルが付いてから行う**
- 本人の裁定は、拡張の出力を見ずに行う（裁定の画面に拡張の値を出さない）。裁定が拡張の結果に引きずられないようにするため
- 裁定を終えた `final.jsonl` の sha256 を、採点の前に REPORT に書く

**2026-11-25 の裁定の記録（逸脱、§2 の 2）**: 上の「本人の裁定」は、本人の決定（2026-11-25）で、次の 3 つの経路を合わせて行った。判定画面の 559 値（割れ・不完全と、一致した値からの抜き取り）の内訳は、本人 325、Fable 182、機械的な採用 52。

1. **Fable（`claude-fable-5-2`、推論の強さ medium）の裁定**: 本人の指示（「不一致のあとの裁定について fable medium にやらせて、迷うとしたものだけ私に回して」）による。Fable には報告の本文と図、レビューの時点の決まり、2 人の読み手の判定だけを渡し、拡張の出力は渡していない。Fable の裁定は、確信が sure で、本文の引用が報告に逐語であり、その数を含むもの（図からの裁定と「本文に無い」は、どちらかの読み手と一致するもの）だけを採り、ほかは本人に回した。途中で本人が決めた規則（レビュー独自の補正をした値・粗い精度の値・時点・gold の誤り・補正した効果量・「別の数」は同じ量のときに限る、の 6 つ）で、Fable の裁定を見直させた
2. **機械的な採用**: 本人の指示で、読み手 2 人がともに「計算できる」または「本文に無い」とした抜き取りの値を、そのラベルで確定した。抜き取りは一致した値の正しさを確かめるためのものなので、この 2 つのラベルについては、その確認を省いたことになる
3. **同じ入力の値**: gold と読み手 2 人の答えがまったく同じ値（解析の名前だけが違うもの）は、1 つの判定を組の全部に写した。本人の判定が組の中で食い違っていた Stanton 2013 は、本人の指示で「載っている」に揃えた

裁定は、本走（§7.1）の run が揃った後に行ったが、採点はしておらず、裁定の画面にも Fable への入力にも拡張の値は出していない。確定した `final.jsonl`（cc-by-nc）の sha256 は `a970afd419420cdf15e33e14747680a07e8ae04f3a47872fb3600a4a0e853498`。final を作り直したことで、渡した文書だけでの再チェックの対象が 16 値増えた（EMERGE 2022 と TRAILBLAZER-ALZ 2）。これは前回の 77 値と同じ 2 人の読み手で読み、16 値すべてが「本文に無い」で一致した。再チェックのラベル（93 値）の sha256 は `42ed65646b8bfca998f1edd1df4884ab75844a3a9ef76c4c8595bbdeeef3cbbd`。REPORT では、経路ごとの値の数と、Fable の裁定を本人が直した件数（「別の数」を「本文に無い」に直した 8 値など）を書く

### 4.4 拡張に渡すもの

- 抽出の項目は、課題ファイルの `items` から作る。1 項目を `outcome_result` の 1 組とし、群は課題の `experimental_group_label` と `control_group_label` で名前を付けて 2 群を明示する（群の番号の取り違えで採点が崩れないようにするため）
- 渡す文脈: 解析名・アウトカム名・群の名前・データの種類・`footnotes`（時点や群の合わせ方が書かれている）・`review_context`（レビューの Methods から写した時点の規則と、アウトカムの定義）
- 渡さないもの: gold の数値、参照のラベル、出所の区分
- 1 研究につき 1 回の依頼で、その研究の項目をすべて頼む（1 研究あたりの項目は少ない。本番は項目を複数の依頼に分けるので、この点が本番と違う。REPORT の限界に書く）
- 項目からスキーマへの変換の詳細は、#356 の採点ハーネスの PR で書き、この計画書へリンクを足す。変換は gold を見ずに決まるもの（項目の文字列だけを使う）に限る

### 4.5 採点の単位と一致の判定

- 単位は 1 つの値（例: ある解析のある研究の、実験群の events）
- 一致の判定は、既存の `matchesValueNumeric`（`experiments/extraction-benchmark-real/src/metrics.ts`）: 前後の空白・NFKC などの正規化の後の文字列の一致か、数として読めるなら表記の差（末尾の 0、桁区切り、中点の小数点、全角のマイナス）を除いた一致。**単位の換算と丸めはしない**
- 拡張が「報告なし」と答えた値は、値を返さなかったものとして扱う
- 失敗した run（§7.3）の値は、すべて不一致として分母に残す

## 5. 評価 A の指標

### 5.1 参照のラベル

Cochrane-bench の参照の照合は、gold の各値に、本文と突き合わせたラベルを付けている（2 人の読み手の独立の判定と、割れたものへの本人の裁定）。

| ラベル | 意味 | 正しい答え |
|---|---|---|
| `reported` | gold の数値が、渡した本文（図を含む）にそのまま載っている | gold の数値 |
| `derivable` | 本文の数値から計算すれば出る（SE から SD など） | 拡張は換算しない設計なので、正解を定めない（§5.3 で別に数える） |
| `different_value` | 本文にあるのは gold と別の数値（gold の側の誤り） | 主・副の分母から外し、件数だけを書く |
| `not_in_documents` | 渡した本文に無い（補足資料、登録簿、著者からの提供など） | 「報告なし」 |

図にだけ載る数値も `reported` に入る（2026-11-09 の Cochrane-bench の決定）。拡張は文字だけを読むので、この分は取れない。図にだけ載る値は §5.3 で別に数える。

### 5.2 主指標

**レビュー単位の感度**: ラベルが `reported` の値のうち、拡張が gold と一致する数値を返した割合。

1. 各モデル 1 反復の run で、レビューごとに「一致した `reported` の値 ÷ `reported` の値」を出す
2. 17 レビューの単純平均を主の値とする（研究の多いレビューに引っ張られないため。#356 の方針）

反復は 1 回なので、反復の間の SD は出さない（§1.1）。この定義は、CESAR のプロトコルの Sensitivity（"The proportion of available data items that were correctly extracted"）に合わせた。95% 信頼区間は、レビューを再抽出し、その中で研究を再抽出する 2 段のブートストラップ（2,000 回、乱数の種 20261122、パーセンタイル法）で出す。この区間は研究の選ばれ方による揺れだけを表し、流し直したときのモデルの揺れは含まない。

### 5.3 副指標

| 指標 | 分子 | 分母 |
|---|---|---|
| 研究をまとめた感度（micro） | 一致した `reported` の値 | `reported` の値（全レビュー） |
| 誤った値の割合 | 拡張が gold と違う数値を返した `reported` の値 | `reported` の値 |
| 報告なしの見落とし | 拡張が「報告なし」と答えた `reported` の値 | `reported` の値 |
| 本文に無い値への回答 | 拡張が数値を返した `not_in_documents` の値 | `not_in_documents` の値 |
| 正確度（CESAR の Accuracy に対応） | 一致した `reported` + 「報告なし」と答えた `not_in_documents` | `reported` + `not_in_documents` |
| `derivable` の一致 | 拡張が gold と一致する数値を返した `derivable` の値 | `derivable` の値 |
| gold そのものとの一致 | gold と一致した値（ラベルを使わない） | gold の全値。Cochrane-bench の基準値（cc-by の Haiku 0.230）と比べるため |
| 引用の照合成功率 | `anchor_status` が `failed` でない引用 | 引用の付いた値 |
| 費用 | 応答の usage のトークン × 単価（思考のトークンは出力として数える）。1 研究あたり | 研究 |
| 応答時間 | 1 依頼の所要秒の中央値と平均 | 依頼 |
| 失敗した run | §7.3 で失敗とした run の数 | run |

層別（いずれも主指標と同じ定義）: 層（cc-by / cc-by-nc）、データの種類（二値 / 連続）、値の種類（events・N・mean・SD）、出所の区分（`derived_suspected` / `unknown`）、図にだけ載る値かどうか。

**誤りの内訳**（#356 の受け入れ条件）: 一致しなかった `reported` の値を、コードで次の順に分ける。

1. 報告なしと答えた
2. 同じ項目の反対の群の gold と一致する（群の取り違え）
3. 同じ研究の別の項目の、同じ群の gold と一致する（解析か時点の取り違えの疑い）
4. それ以外の数値の違い

4 の中を「時点の取り違え」「読み違い」「その他」に分けるのは事後の解析とし、2 人の読み手（Claude のサブエージェントと codex）が独立に分け、割れたものを本人が決める。

### 5.4 比較の読み方

- 比較モデル（Sonnet 5.5・Haiku 5.5）ごとに、既定の 3.8 Flash との主指標の差と、その 95% 信頼区間（§5.2 と同じブートストラップで、同じ再抽出の中の差）で示す。Sonnet 5.5 と Haiku 5.5 の間の差は主に扱わない。**区間が 0 をまたぐなら、差があるとは書かない**
- 検定はしない
- CESAR のデータ抽出の中止境界（感度の点推定 92%、重大エラーの割合の点推定 3%）を参考値として並べる。この評価の「誤った値の割合」は、結論を誤らせうるかを問わずに数えるので、CESAR の重大エラーより広い。境界を下回っても上回っても、拡張の合否は判定しない（拡張は人の検証を前提にしている）
