# 論文 Methods 記載例（エクスポート画面のコピー用文案）

S10（`#/export`）に表示する「論文の Methods セクションにこう書ける」記載例の正典。エクスポート画面にカードとして表示し、ワンクリックでクリップボードへコピーできるようにする（[requirements.md §4.4](requirements.md)、[ui-states.md `#/export`](ui-states.md)）。

- 記載例は **言語（English / 日本語）× ワークフロー（単一レビュアー検証 / 二重独立検証）** の組み合わせで出す。
- 文は**記録（ExtractionRuns・LLMApiLog・SchemaVersions・StudyData / ResultsData・Decisions）と合う形だけ**を出す。記録から言えないこと（全項目を抽出した・全セルを判定した・草案を AI が作った 等）は、記録がそう示すときにしか書かない（issue #381）。文の出し分けの条件は §1〜§2 の各文に付ける。
- 英語は数に応じて単数形・複数形（study/studies、cell/cells、once/times など）を切り替える。日本語は変えない。
- `{{...}}` はプレースホルダ。自動反映できるものはプロジェクトの実績値で埋め、埋められないものはプレースホルダのまま表示してユーザーに編集を促す（§3）。
- 内容は PRISMA 2020 チェックリスト item 9（data collection process: レビュアー数・独立性・自動化ツールの詳細）を満たすことを意図している。
- **これは記載例であり、そのまま使える文ではない。** 数値・人数・手順が実際と一致しているかは、ユーザーが必ず確かめて直す（カードの説明文で常に示す。§4）。

文案は 1 段落目（ツール・フォーム）+ 2 段落目（事前抽出・検証）+ オプション文（末尾）の順に、下の文を条件に合うものだけつなげて組み立てる。英語・日本語とも同じ条件で出し分ける。

## 3. プレースホルダ一覧と自動反映元

| プレースホルダ | 内容 | 自動反映元 |
| --- | --- | --- |
| `{{tool_version}}` | 拡張のバージョン | `chrome.runtime.getManifest().version`。**抽出時ではなく、今インストールしている版**（抽出時の版は記録に無い。カードの説明文で示す） |
| `{{draft_model_id}}` | フォームの草案を作ったモデル | `LLMApiLog`（`purpose = draft_schema` の成功した呼び出し）の `model`。要求したモデル ID。複数は列挙 |
| `{{draft_provider}}` | 草案の API プロバイダ名 | 同じ行の `provider`（表示名に変換） |
| `{{model_id}}` | 事前抽出に使ったモデル | 事前抽出に成功した完了 run（全 `run_type`）の `model_version`。空なら `requested_model`（要求したモデル ID。このときはカードの説明文で示す）。新しい順・重複除去で列挙 |
| `{{provider}}` | 事前抽出の API プロバイダ名 | 同じ run の `ExtractionRuns.provider`（`gemini` → `Gemini` 等の表示名変換） |
| `{{n_sample}}` | スキーマドラフトに渡したサンプル論文数 | 記録に無いためプレースホルダのまま |
| `{{n_pilot}}` | パイロット抽出に成功した研究数 | `run_type = pilot` の完了 run で事前抽出に成功した採用研究の数（重複除去）。0 なら反映しない |
| `{{n_form_revision}}` | フォームの改訂回数 | `SchemaVersions` の版数 − 1 |
| `{{n_included}}` | 採用研究数 | エクスポート対象の研究（Documents から参照される研究）の数。0 なら反映しない |
| `{{n_extracted}}` | 事前抽出に成功した採用研究数 | 下の「事前抽出の成功の判定」。0 なら反映しない |
| `{{n_not_extracted}}` | 事前抽出が届かなかった採用研究数 | `n_included − n_extracted` |
| `{{n_partial}}` | 全項目の事前抽出を確かめられない研究数 | 下の「事前抽出の成功の判定」 |
| `{{n_unverified}}` | 未検証のセル数 | R セットの未検証セル数 |
| `{{n_scanned}}` | `no_text_layer` の document 数 | `Documents.text_status` の集計。0 件ならオプション文自体を出さない |
| `{{n_pilot_revision}}` | パイロットの判定に基づく抽出指示の改訂回数 | `SchemaVersions` の `created_by_type = pilot_revision` の版数。0 件ならオプション文自体を出さない |
| `{{reviewer_initials}}` | レビュアーのイニシャル | 自動反映しない |
| `{{adjudicator_initials}}` | 裁定者のイニシャル | 自動反映しない |
| `{{supplement_ref}}` | audit.csv を載せる補足資料の番号（例: Supplementary Table S1） | 自動反映しない |

### 事前抽出の成功の判定

- 対象は `ExtractionRuns` の完了行（`status = done` / `partial_failure`）を持つ run（全 `run_type`）。完了行の無い run（中断）は数えない。
- run が対象にした研究のうち、`LLMApiLog` に同じ `run_id`・`study_id` の `[batch_failed]` 行が無い研究は成功とする。失敗行がある研究も、同じ run・研究の失敗していない節に成功した `extract_study` 呼び出し（警告専用でなく `error` が空）があれば、部分的な抽出として成功に数え、その run のモデルも列挙する。その成功行が無ければ、その run では失敗とする。
- 研究は、成功した run が 1 つ以上あれば「事前抽出に成功した」（`n_extracted`）。
- 成功した run のうち、次のすべてを満たす run が 1 つも無い研究は「全項目の事前抽出を確かめられない」（`n_partial`）。別の run で全項目の抽出を確認できれば部分には数えない:
  - `field_ids` が空（全項目の実行）
  - 同じ run・研究に `[batch_failed]` 行が無い
  - 同じ run に `[transfer_failed]` 行が無い（転記失敗がある run は、研究別のバッチ失敗の有無にかかわらず全項目の根拠にしない）
  - `status = done`、または `partial_failure` で同じ run に `[batch_failed]` 行がある（失敗の原因が研究単位で分かる）。`partial_failure` で `[batch_failed]` 行が無い run は、AI 出力の一部の破棄・保存失敗など研究を特定できない失敗を含むため、全項目とはみなさない。
- 限界: `[batch_failed]` 行がある `partial_failure` の run で、別の研究に要素の破棄が重なっていても、研究単位の記録が無いため区別できない。

## 4. UI 仕様メモ（S10 カード）

- `#/export` の形式選択カードの下に「論文 Methods 記載例」カードを置く。
- 切替: 言語タブ（English / 日本語。既定は English — 投稿論文の主想定言語）× ワークフロートグル（単一レビュアー / 二重独立）。ワークフローの初期値は記録から決める: `StudyData` / `ResultsData` に `consensus` または `human_independent` の行があれば二重独立、なければ単一レビュアー（R セットの `review_mode` と同じ導出〔`deriveReviewMode`〕）。手動の切り替えは残す（初回の読み込み時だけ初期値を入れ、再読み込みではユーザーの切り替えを上書きしない）。
- 本文は読み取り専用の複数行表示 + 「コピー」ボタン（`navigator.clipboard.writeText`）。成功時は「コピーしました」フィードバック（tiab-review のトースト トンマナ）。
- カードの説明文（本文の下）:
