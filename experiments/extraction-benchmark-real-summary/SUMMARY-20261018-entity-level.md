# 実データ抽出ベンチマーク 項目の区分ごとの誤りの集計（issue #377 段階 1・2026-10-18）

不眠治療の SR に含まれる RCT 10 本の保存済みの抽出結果を、項目の区分ごとに人手の正解（gold）と比べ直した集計です。LLM は呼んでいません。公開するのは件数と割合だけで、原論文・gold・個々の抽出結果は公開していません（`experiments/extraction-benchmark-real/` は `.gitignore` 対象）。

## 結論

1. 既定モデル `gemini-3.8-flash` では、アウトカムの数値の正確度は 77.8% で、ほかの 3 区分を合算した 73.6% より **4.2 ポイント高い**。集計の前に決めた基準（アウトカムがほかより 5 ポイント以上低ければ段階 2 へ）に照らして、**段階 2（項目群ごとに分けて抽出する 3 構成の比較）には進まない**。
2. 正確度がいちばん低いのは研究の基本情報（52.3%）で、次が背景因子（68.9%）。誤りの多くは「値の誤り」で、行の欠落と出力上限での打ち切りは 0 件だった。
3. 群の数が gold と違う run は 4 モデルとも 0 本。群の並びが gold と違ったのは `gemini-3.5-flash` の 1 本だけで、既定モデルでは 0 本だった。項目群ごとに分けて「群を先に確定する段」を足しても、既定モデルで直せる誤りはほぼ無い。

ベンチのスキーマは `study` 13 項目と `arm` 55 項目だけで、アウトカムの数値は arm の列として入っています。`outcome_result` と `rob_domain` の区分はありません。そこで 68 項目を内容で 4 区分に分けました（集計の前に issue #377 のコメントで確定）。

### 誤りの内訳（既定モデル `gemini-3.8-flash`）

| 区分 | 誤り | 行の欠落 | 未報告の見落とし | 余分な値 | 値の誤り |
| --- | ---: | ---: | ---: | ---: | ---: |
| 研究の基本情報 | 62 | 0 | 12（19.4%） | 18（29.0%） | 32（51.6%） |
| 群の記述 | 64 | 0 | 0 | 0 | 64（100%） |
| 背景因子 | 56 | 0 | 24（42.9%） | 6（10.7%） | 26（46.4%） |
| アウトカムの数値 | 120 | 0 | 24（20.0%） | 51（42.5%） | 45（37.5%） |
| 合計 | 302 | 0 | 60（19.9%） | 75（24.8%） | 167（55.3%） |

- 行の欠落: AI がその項目 × 群の行を出していない

- 値の誤り: gold も AI も値ありで、値が一致しない

### 群のずれと打ち切り

| モデル | 群の数が gold と違う run | 群の並びが gold と違う run | その run の群の項目の誤り | 出力上限での打ち切り |
| --- | ---: | ---: | ---: | ---: |
| 3.8 Flash | 0 | 0 | 0 | 0 |
| 3.5 Flash | 0 | 1（Rybarczyk2011） | 56 | 0 |
| 3.1 Flash Lite | 0 | 0 | 0 | 0 |
| 3.5 Flash Lite | 0 | 0 | 0 | 0 |

- 群の並びのずれは、gold と AI の群の対応をすべて試し、正確度が上がる対応がある run を数えました。
- 「その run の群の項目の誤り」は、その run の群の項目の誤りをすべて数えた**上限の目安**です。対応を取り直しても残る誤りも含みます。
- 打ち切りは、採用されなかった試行（429 で失敗した 3 試行）も含めて数えました。

## 読み方

- 誤りがアウトカムの数値に偏っているなら、アウトカムだけを別の呼び出しで深く読ませる案に意味があります。既定モデルでは逆で、アウトカムの数値は全体より正確でした。
- 研究の基本情報が低いのは、自由記述の項目（寛解の定義・併存症・診断基準など）を文字列の一致で採点しているためでもあります。言い換えでも不一致になるので、この区分の正確度は下限寄りです。
- 背景因子の「未報告の見落とし」には、gold 側の取り決めの値（0 人、計算した SD など、論文に明示されていない値）が含まれます（2026-10-04 の調べ）。

## 限界

- 各モデル 1 反復。過去の 3.1 Flash Lite の 3 反復では反復間の SD が 1.6 ポイントあった。差の 4.2 ポイントは基準の 5 ポイントに近いが、向きは「アウトカムの方が高い」で、基準を満たす向きではない。
- 10 本はすべて 2 群の試験（群の重複を直した後の gold）。3 群以上の試験での群のずれは測れていない。
- RoB は測れていない。

区分ごとの正確度:

| 区分 | Gemini 3.8 Flash | Sol 6.1 | Sonnet 5.5 |
| --- | ---: | ---: | ---: |
| 研究の基本情報 | 50.8% | 47.7% | 45.4% |
| 群の記述 | 81.6% | 35.3% | 36.8% |
| 背景因子 | 70.6% | 60.6% | 51.1% |

- 差の大部分は、gold の取り決めの値の扱いから来ています。治療の構成要素のフラグ 17 個は、論文にその要素が無ければ gold は 0 です。Gemini は 0 と返し、Sol は「未報告」と返し、Sonnet は行そのものを出しませんでした。本番プロンプトの「書かれていない値を推し量らない」を、後の 2 モデルは厳密に守った形です。
- Sonnet は、プロンプトが「未報告の項目も not_reported: true で返す」と求めているのに、値のある項目だけを返しました（597 行が欠落）。構造化出力が保証するのは 1 件ごとの形だけで、全項目を返すことまでは強制しません。
- 「未報告と返した行を正解に数えた場合」は、gold の取り決めの値まで AI に求めない読み方です。この読み方では Sol と Gemini はほぼ同じです。
- 費用は参考値です。Gemini は 0.079 USD/論文（実測、2026-12-31 までの割引単価）。Sol は報告されたトークン数に第三者サイトの単価（入力 2.00 / 出力 10.00 USD/100 万トークン、未確認）を掛けて約 0.16 USD/論文。Sonnet は CLI が出した概算で 0.18 USD/論文。Sol と Sonnet は今回、それぞれのサブスクリプションの利用枠で動かしました。
