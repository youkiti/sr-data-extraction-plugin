## 1. 何を判定するか

段階 2 で試作する「図の数値読み取り」（以下、**図読み取りモード**。S7 一括抽出のオプトイン、既定オフ）を、本番に残すか撤去するか。

図読み取りモードの構成（issue #265 段階 2 の設計どおり）:

1. テキスト層のキャプション（行頭の `Figure N` / `Fig. N`）で候補ページを絞る
2. 候補ページの画像（`renderPdfPageToCanvas`、scale 2.0）を Gemini に渡し、データチャートごとに `box_2d`・キャプション番号・表（`columns[]` × `rows[][]`、軸ラベル・軸範囲・ばらつきの指標・confidence）を返させる（新 skill `digitize-figure`）
3. その表を `[FIGURE-DERIVED TABLE fig:<id> page p — machine-read from a chart; approximate]` 付きのパイプ表として本文の後に足し、抽出 LLM に渡す（`EXTRACT_DATA_PROMPT_VERSION` を上げる。本文・表に同じ値があればそちらを優先する規約）

比べる条件は 2 つ:

| 条件 | 内容 |
|---|---|
| **OFF** | 現行の本番どおり（テキストのみ、プロンプト版数は段階 2 の新版数。図由来の表を足さない） |
| **ON** | 図読み取りモードを有効にし、図由来の表を足す |

- OFF 側も段階 2 の新しいプロンプト版数で走らせる（版数の違いと図読み取りの効果を交絡させないため）。あわせて、現行版数 9 の OFF を 1 回走らせ、新版数の OFF が版数 9 から劣化していないことを確認する（§4.3）
- モデルは `gemini-3.5-flash`（工場出荷の既定。Gemini だけが `box_2d` を返すため）。temperature 0、構造化出力
- 図の読み取りと抽出はどちらも同じモデルで行う

## 2. データセット

[SURVEY.md](SURVEY.md) §4 の結論に従い、2 つの集合を使う。

### 2.1 図ベンチ（新設・非公開）

**結果が図にしか無い RCT を 15〜20 本**集め、人が WebPlotDigitizer で読んだ値を正解（gold）にする。

- **選定基準**
  1. RCT（クロスオーバー・クラスターも可）で、born-digital の PDF（テキスト層あり。スキャン PDF は対象外 = issue #265 の範囲外）
  2. 少なくとも 1 つの主要アウトカムの群別の値（平均・ばらつき、または割合、生存確率）が**図にしか無い**（本文・表・補足資料の本文にも数値が無い）ことを、人が確認したもの
  3. 図の種類を散らす（目標構成 **案**: 平均 ± SE/SD の折れ線 ≥ 5 本、エラーバー付き棒グラフ ≥ 5 本、KM 曲線 ≥ 3 本、その他〔箱ひげ図・散布図〕≥ 2 本）
  4. 群数を散らす（3 群以上の試験を ≥ 3 本）
  5. 可能な限り PMC OA の CC BY 論文から選ぶ（将来 PDF と gold を公開する選択肢を残すため。§2.3）
- **gold の作り方**
  1. 2 人が**独立に** WebPlotDigitizer で読む（軸の校正点を記録する）。gold = 2 人の値の平均
  2. 2 人の差が軸範囲の 2% を超える点は、3 人目が読んで裁定する
  3. 図ごとに `figure_label`・ページ・`is_data_chart`・軸ラベル・軸範囲・ばらつきの指標（キャプション・凡例に書かれたもの。書かれていなければ `not_stated`）を記録する
  4. 点ごとに `group`・`x`（時点など）・`y`・エラーバーの上端と下端（あれば）を記録する
  5. KM 曲線は、決めた時点（例: 6・12・24 か月）の生存確率と、図の下の number at risk（あれば）を記録する
  6. 抽出スキーマ（§2.4）の項目に当たる行は、既存 gold と同じ形式（`field_id` × `entity_key`、`value_gold`・`acceptable_values`・`not_reported`）でも持つ
  7. 行ごとに `source_kind`（`figure_only` / `text` / `both`）と `source_page` を記録する（#176 で `source_page` が空だったために表由来の効果を分離できなかった反省）
- **人の読み取りのばらつき**: 2 人の差（軸範囲比）の分布を必ず報告する。LLM の誤差はこの分布と並べて解釈する
- **保管**: `experiments/figure-digitize-benchmark/private/`（`.gitignore` 対象。段階 2 で追加する）。PDF・gold・個々の run はコミットしない。集計だけを公開する（`experiments/extraction-benchmark-real-summary/` と同じ運用）

### 2.2 回帰ベンチ（既存・非公開）

既存の不眠 SR 10 本（`experiments/extraction-benchmark-real/`、68 項目、gold 1,340 行）。図読み取りモードを ON にしても、**テキストと表から取れていた項目が悪くならない**ことを確かめる。

### 2.3 公開ベンチの扱い

[SURVEY.md](SURVEY.md) の結論のとおり、採否の判定には公開ベンチを使わない（医学 RCT の図と条件が大きく違うため）。段階 2 の開発中の動作確認（点の読み取り誤差の目安）にだけ使ってよい。その結果は判定に入れない。

### 2.4 図ベンチの抽出スキーマ

既存の 68 項目スキーマのうち、図ベンチの論文に当てはまる項目（study / arm 項目の一部 + outcome_result）を使い、図にしか無いアウトカムの項目（例: 「主要アウトカムの各時点の群別平均」「同 SD または SE」「12 か月生存確率」）を論文ごとに足す。スキーマは**段階 2 の実行前に固定**し、変更したら REPORT に記録する。

## 3. 評価指標

### 3.1 図の読み取りそのもの（`digitize-figure` の出力を gold の点と直接比べる）

| # | 指標 | 分子 | 分母 |
|---|---|---|---|
| D1 | **点ごとの誤差が軸範囲の ±2% 以内の割合** | \|LLM の y − gold の y\| ÷ (gold の y 軸の上限 − 下限) ≤ 0.02 の点の数 | gold の全データ点（LLM が出さなかった点は不合格として分母に残す） |
| D2 | **群の順位の正答率** | 大小の向き（どちらの群が大きいか）が gold と一致した群の対の数 | 同じ (図, x) の中の**群の全ての対**のうち、gold で 2 群の差が軸範囲の 2% 以上ある対（2% 未満の対は「区別できない」としてその対だけを除外する。3 群以上の図でも対ごとに判定する）。LLM がどちらかの群の点を出さなかった対は不正解として分母に残す |
| D3 | **ばらつきの指標の正答率** | `dispersion_measure`（SD / SE / 95% CI / IQR / range / `not_stated`）が gold と一致した図の数 | gold の全データチャート |
| D4 | エラーバーの誤差が軸範囲の ±2% 以内の割合（補助） | エラーバーの上端・下端のそれぞれで D1 と同じ判定 | gold にエラーバーがある点の端点 |
| D5 | データチャートの検出（補助） | 感度 = LLM が見つけた gold のデータチャート数、適合率 = LLM が返したチャートのうち gold のデータチャートである数 | gold のデータチャート数 / LLM が返したチャート数 |

- 点の対応: (図, 群, x) で突き合わせる。群名の対応は凡例の文字列で取り、取れないときは人が対応を付けて REPORT に記録する（既存ベンチの arm の対応付けと同じ）
- x の対応: x が連続値（時間）の図は、同じ (図, 群) の中で gold の点と LLM の点を**一対一**に対応させる。|x の差| の小さい組から順に確定させ（1 つの LLM の点は 1 つの gold の点にしか使わない）、x 軸範囲の 2% 以内の組だけを同じ点とみなす。対応が付かなかった gold の点は「LLM が出さなかった点」として扱う
- D2 の分母（対の数）は gold だけで決まるので、LLM を走らせる前に数える。**40 組未満**（**案**）なら図ベンチの構成が足りないので、実行前に論文を足す
- 軸範囲は gold 側（人が校正に使った範囲）を使う。対数軸の図は log 変換後の範囲で測る

### 3.2 抽出の結果（図ベンチ、OFF と ON を比べる）

| # | 指標 | 定義 |
|---|---|---|
| E1 | **図にしか無い項目で NR → 正解になった件数** | `source_kind = figure_only` の gold 行のうち、OFF で `not_reported`（または不正解）かつ ON で正解の行数。あわせて割合（分母 = `figure_only` の gold 行数）と、逆向き（OFF 正解 → ON 不正解）の件数も出す |
| E2 | 図由来の値の正解判定 | 数値は「gold との差が軸範囲の 2% 以内」を正解とする（既存ベンチの完全一致では判定しない。人の読み取りも誤差を持つため）。文字列（群名など）は既存ベンチ §4.0 と同じ正規化後の完全一致 |
| E3 | 図由来の値の重大エラー | ON で返した図由来の値のうち、gold との差が軸範囲の 5% を超えるもの、または別の群・別の時点の値を取り違えたもの |
| E4 | テキスト優先の破れ | gold の `source_kind` が `text` または `both` の行で、ON が図由来の表の行を quote にした件数（本文・表にある値を図の近似値で置き換えた件数） |
| E5 | 既存指標 | 項目正確度・未報告の感度 / 特異度・照合成功率・重大エラー率（既存ベンチ §4 と同じ定義）。照合成功率は `source_kind` 別に分けて出す |

### 3.3 回帰ベンチ（既存 10 本、OFF と ON を比べる）

既存ベンチ §4 の指標をそのまま使う: 全体の項目正確度、照合成功率、未報告の特異度、重大エラー率、format / transport error 率。

- **集計の仕方**（A6〜A8 の判定値）: 各 run（1 論文 × 1 反復）で指標を出し、条件ごとに「10 本の平均」を反復ごとに求め、さらに 2 反復の平均を取る（SUMMARY-20260921 の「run ごとの正確度の 10 本平均」と同じ重み付け = 論文を等しく重み付けする）。判定は ON と OFF のこの値の差で行う。反復ごとの差と、論文ごとの差（2 反復の平均の対応のある差）もあわせて報告する
- 照合成功率は、既存ベンチと同じく quote が null でない行を分母にする。ON で図由来の表の行を quote にした行は、A7 の判定では分母から除き、別に件数を報告する（図由来の quote は PDF のテキスト層ではなく図の bbox に結びつくため）

### 3.4 コスト・時間

- 1 論文あたりのコスト = 図の読み取りの呼び出し + 抽出の呼び出しの実測 tokens（思考トークンを出力として数える）× `pricing.ts` の単価
- 応答時間 = 1 論文の一括抽出にかかる実時間（図の読み取りを含む）

## 4. 採用基準

### 4.1 主基準（すべて満たしたら採用）

| # | 基準 | 閾値 | 根拠 |
|---|---|---|---|
| A1 | 図にしか無い項目の回収（E1） | E1 の件数（OFF で正解でなく、ON で正解になった `figure_only` 行）が `figure_only` gold 行の **50% 以上**（**案**）。かつ、それらの行が **5 本以上の論文**にまたがる | 現状は構造上ほぼ 0%（テキストに無いので NR にしかならない）。半分取れれば、人が WebPlotDigitizer を起動する回数を目に見えて減らせる。1〜2 本の論文だけの効果で採用しないため論文数も課す（#176 の「特定の 1 論文に依存しない」と同じ趣旨） |
| A2 | 点ごとの誤差（D1） | ±2% 以内が **80% 以上**（**案**） | issue #265 の案の ±2%。人の読み取り同士の差の分布（§2.1）で妥当性を確かめる（§4.4） |
| A3 | 群の順位（D2） | **95% 以上**（**案**） | 順位の取り違えは効果の向きを逆にする最悪の誤りなので、点の誤差より厳しくする |
| A4 | ばらつきの指標（D3） | **90% 以上**（**案**）。キャプションに書いていないものを推測で SD / SE と答えた図は、件数を別に報告する | SD と SE の取り違えは効果量の標準誤差を √n 倍ずらす。書かれていない場合は `not_stated` と答えるのが正解 |
| A5 | 図由来の値の安全性（E3・E4） | E3 の重大エラー率が ON で返した図由来の値の **10% 以下**（**案**）。E4 のテキスト優先の破れが**図ベンチと回帰ベンチの合計で 0 件**（**案**。1 件でもあれば未達。例外は設けない） | EviStreams で Datalab のチャート読み取りが「measurably wrong」な値をエクスポートまで届けた実例がある（issue #265）。人の確認を前提にしても、誤りの多い下書きは確認の負担を増やす。本文・表の正確な値を図の近似値で置き換えるのは、図読み取りを入れる前には起きなかった劣化なので許さない |
| A6 | 回帰ベンチの全体正確度（非劣性） | ON − OFF ≥ **−2 ポイント**（**案**） | 既存ベンチの反復間 SD は約 1.6 ポイント（SUMMARY-20260921 の「限界」）。#176 は 5 ポイントだったが、既存 10 本の gold は表・本文由来で、図読み取りで良くなる余地がほぼ無いので、悪化の許容幅を狭くする |
| A7 | 回帰ベンチの照合成功率 | ON で **90% 以上**、かつ ON − OFF ≥ **−2 ポイント**（**案**） | 既存ベンチの足切り（90%）と、#176 で −1.1 ポイントを観測したことから |
| A8 | 回帰ベンチの未報告の特異度・重大エラー率 | 特異度が悪化しない（ON − OFF ≥ −2 ポイント）、重大エラー率が増えない（ON − OFF ≤ +2 ポイント）（**案**） | #176 の基準に合わせ、1 反復の揺れの分だけ幅を持たせる |
| A9 | 追加コスト | 1 論文あたりの平均コストが、**回帰ベンチで +20% 以内**（issue #265 の案）。図ベンチの増分は報告するが判定に使わない（**案**） | 図の多い論文ほど増えるのは当然なので、判定は典型的な論文（回帰ベンチ）で行う。図ベンチの増分は S7 の概算表示の妥当性確認に使う |
| A10 | 失敗率 | 「失敗した論文」の割合が、ON で OFF を上回らない（図ベンチ・回帰ベンチを合わせて数える） | #176 で画像追加により format error 10% が新たに出た反省。**失敗した論文** = その論文の処理（ON なら図の読み取りの呼び出しを含む）で、通常の 1 回リトライの後も format / transport error が残った呼び出しが 1 つでもある論文。図の読み取りだけが失敗して抽出が完了した論文も失敗に数える。分母 = 論文数 × 反復数 |

### 4.2 判定の手順

1. A1〜A10 をすべて満たす → **採用**。issue #265 の段階 3 の「採用した場合」の後続 issue（図と表を並べて確認する画面、エクスポートでの図由来の印、他プロバイダへの展開）を起こす
2. A1 以外をすべて満たし、A1 だけ届かない → 原因（図の検出漏れか、抽出が図由来の表を使わないのか）を E1 の内訳で調べて REPORT に書き、**不採用**とする。基準を緩めて採用しない
3. A2〜A10 のどれか 1 つでも満たさない → **不採用**。基準ごとの例外や、結果を見てからのオーナー判断による免除は設けない
4. 不採用のときは #176 と同じく実装を撤去し、`docs/remaining-work-plan.md` の「不採用（記録）」に残す

### 4.3 前提の確認（判定の前に行う）

- 新しいプロンプト版数の OFF と、現行版数 9 の OFF を回帰ベンチで比べ、全体正確度が 2 ポイントを超えて下がっていないこと。下がっていたら、図読み取り以外の変更が混ざっているので、判定の前に原因を調べる

### 4.4 閾値の見直しを認める唯一の場合

人の 2 人の読み取りの差（§2.1。3 人目の裁定の前の値）のうち、軸範囲の ±2% 以内に収まる点が **90% 未満**だった場合、±2% は人にも達成できない閾値である。そのときに限り、**LLM を走らせる前に**次のとおり置き換え、REPORT に逸脱として記録する。LLM の結果を見た後の変更は認めない。

- 新しい閾値 T = 人同士の差（軸範囲比）の 90 パーセンタイル。ただし **T の上限は 4%**（**案**）
- D1・D4・E2 の ±2% と、D2 の「区別できない」幅の 2% を T に置き換える。x の対応の 2% はそのままにする
- E3 の重大エラーの 5% を 2.5 × T に置き換える（元の 2% と 5% の比を保ち、E2 の正解と E3 の重大エラーが重ならないようにする）
- T が 4% を超える（人同士でも 90% の点が ±4% に収まらない）場合は、閾値を緩めるのではなく gold の作り方（軸の校正、図の解像度、読む人の手順）に問題があるとみなし、gold を作り直してから同じ確認をやり直す
